## Verified Architecture Direction

Across the current docs, the architecture is now stable on these points:

- internal demo SharePoint lists are the only approved write targets
- no production hospital systems may be written
- patient-related content must remain fake, synthetic, or anonymized
- Code Alert workflow behavior is app-owned and release-controlled, not SharePoint-rule-driven
- the switchboard shell owns popup takeover, focus safety, queue behavior, and guarded close
- the remote Originator writes append-only intake receipts and does not talk directly to secured `CodeAlerts`

The docs are consistent that the operator console must remain plain, boring, obvious, and fast under stress. Hidden state, clever layout, and admin-editable workflow logic remain out of bounds.
