## Safety Boundary

This remains a SharePoint/SPFx proof-of-concept only.

- No production hospital writes.
- No PHI or real patient data.
- No real patient identifiers, MRNs, DOBs, SSNs, or clinical details tied to real people.
- Epic, Riskmaster, MedTrak, paging, alarm, phone-directory, and external workflow actions are mocked or internal-demo only unless explicitly approved as read-only.
- Code Alert contact names and phone numbers in source material must be represented with placeholders in repo/demo artifacts.

Before adding persistence or integration behavior, verify:

1. Writes go only to internal demo SharePoint lists.
2. Data is fake/synthetic.
3. External systems are not written to.
4. The UI reduces operator burden.
5. Approved Code Alert language is preserved.

## Code Alert Rule Inventory Direction

User confirmed:

1. The supplied images are final approved source versions.
2. Real contacts should be replaced with placeholders.
3. `CaAlertRules` should store rich text HTML in SharePoint so rules can be edited later.
4. The app should communicate real room/location text entered by the originator/operator.

Design decision:

- Store approved static guidance in `CaProcedureHtml`.
- Do not put scripts, event handlers, or executable bindings in rich text.
- Store interactive controls in `CaActionSchemaJson` and `CaFormSchemaJson`.
- The SPFx web part renders and binds those controls.

Useful first rules for implementation:

- `CaMedicalCodeBlueAdult`
- `CaFacilityFireAlarm`

These are already in:

```text
test-data/sharepoint-lists/CaAlertRules.seed.json
```
